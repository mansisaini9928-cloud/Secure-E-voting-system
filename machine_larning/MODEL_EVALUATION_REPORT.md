# Model Evaluation Report

**Data: SIMULATED.** 12,000 synthetic session windows (seed 42), 5% attacks (brute force, token replay, bot traffic,
credential stuffing). 20% of attacks are "low and slow" and ~10% of normal sessions look suspicious (forgot password,
shared Wi-Fi, heavy refresh), so the classes overlap on purpose. ~1.5% of three features are missing.
Split: 75% train / 25% test, **stratified** (test = 3,000 rows, 150 attacks). Preprocessing is one `Pipeline`
(median imputer -> `StandardScaler` -> model), fit on training data only.

## Models
- **Isolation Forest** (unsupervised): 200 trees, `max_samples=512`, fit on ~99% normal rows (labels unused).
  `contamination` tuned on a validation slice of the *training* data, choosing the best **F2** (recall weighted 2x):
  0.03 (grid 0.01 to 0.15).
- **Random Forest** (supervised comparison): 300 trees, `class_weight="balanced_subsample"`.

## Results on the held-out test set
| Metric | Isolation Forest | Random Forest |
|---|---|---|
| Precision | 0.703 | 0.958 |
| Recall | **0.853** | **0.913** |
| F1 | 0.771 | 0.935 |
| ROC-AUC | 0.987 | 0.998 |
| Accuracy | 0.975 | 0.994 |

Confusion matrices `[[TN, FP], [FN, TP]]`: IF `[[2796, 54], [22, 128]]`, RF `[[2844, 6], [13, 137]]`.

Recall by attack type (IF / RF): brute force 0.79 / 0.76, token replay 0.81 / 0.97, bot traffic 0.80 / 0.90,
credential stuffing 1.00 / 1.00.

## Why recall matters more than accuracy here
Only 5% of sessions are attacks, so a model that says "normal" every time scores **95% accuracy** and catches nothing.
Accuracy is dominated by the easy majority class. **Recall** = share of real attacks caught; a missed attack (false
negative) means a threat nobody reviews, while a false alarm (false positive) costs a human a few minutes. Because
alerts are advisory and reviewed by people, we accept lower precision to keep recall high (hence F2 for tuning).

## Honest reading of the numbers
- Results are on **simulated** data generated by us; real attackers will behave differently. Do not quote these as
  real-world detection rates.
- Random Forest wins because it uses labels; it can only find attack types it has seen. Isolation Forest needs no
  labels and can flag *novel* behaviour, at the cost of more false alarms (54 vs 6 here).
- Both models miss "low and slow" attacks that overlap normal behaviour (e.g. brute force with only 3-6 failures).
- Train/serve skew: live windows must resemble training rows. Traffic with no login events (never seen in
  training) scored as normal until the window builder was adjusted; this is a real deployment risk.
- The model is a triage aid. **It never blocks a vote; a human reviews every alert.**
