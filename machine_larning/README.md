# ML Security Monitoring Module (Member 3)

> **ALL DATA IN THIS MODULE IS SIMULATED.** `dataset.csv` is synthetic (fixed seed 42). The "attacks" are
> generated by `generate_dataset.py`; no real voter, login, or attack traffic was used. Every chart and
> API response is labelled accordingly. Results show the pipeline works, **not** that it would catch real attackers.

**Ethics rules:** the ML never blocks, delays or invalidates a vote. It only writes rows to `security_alerts`
(status `new`) for a human to review. It never reads candidate, ballot or personal data.

## Assumptions (shared contract was not available when this was written)
- Flask + SQLite. DB file: `machine_learning/evoting.db` (override with env var `EVOTING_DB`).
- Member 1's `activity_log` has: `event_type` (`login_success`, `login_failed`, `token_request`, `vote_cast`, `request`),
  `account_ref` (hashed), `ip_hash`, `created_at` (`YYYY-MM-DD HH:MM:SS`, UTC).
  If the real names differ, edit **only** `ACTIVITY_LOG_MAP` / event-name constants in `config.py`.

## Files
| File | Purpose |
|---|---|
| `generate_dataset.py` | 12,000 simulated session windows, 5% attacks, noise + overlap, missing values |
| `preprocessing.py` | split (stratified), `Pipeline(imputer -> StandardScaler -> model)` |
| `train_model.py` | Isolation Forest (contamination tuned) + Random Forest, saves `model.pkl` |
| `evaluate.py` | precision/recall/F1/ROC-AUC/confusion matrix + 4 PNG charts in `outputs/` |
| `detection.py` | `score_activity(record)` -> `anomaly_score`, `severity`, `reason` |
| `api.py` | Flask blueprint: `POST /api/security/score`, `GET /alerts`, `GET /summary` |
| `live_windows.py` | cron-style job: builds windows from the real `activity_log` and scores them |
| `db.py` | creates `activity_log` (if missing) and `security_alerts` |

## Run in VS Code (from the project root, with the integrated terminal)
```bash
python -m venv .venv
.venv\Scripts\activate            # Windows   (macOS/Linux: source .venv/bin/activate)
pip install -r requirements.txt

python machine_learning/generate_dataset.py   # -> dataset.csv
python machine_learning/train_model.py        # -> model.pkl
python machine_learning/evaluate.py           # -> outputs/*.png, outputs/metrics.json
pytest -v                                     # 29 tests

python machine_learning/api.py                # API on http://127.0.0.1:5003
```
In VS Code select the interpreter: `Ctrl+Shift+P` -> *Python: Select Interpreter* -> `.venv`.

## Plug into the team app
```python
from machine_learning.api import security_bp
app.register_blueprint(security_bp)
```
Set `EVOTING_DB` to the team's SQLite file so both modules share `activity_log`.

## Live demo on real `activity_log`
```bash
python machine_learning/live_windows.py --once                 # score the last 5 minutes once
python machine_learning/live_windows.py --every 60             # cron-style, every 60 s
python machine_learning/live_windows.py --seed-demo --once     # add SIMULATED attack traffic first
```
Windows are grouped by `ip_hash`; alerts are de-duplicated per `(ip_hash, window_start)`.
Rows whose `ip_hash` starts with `sim-` are stored with `is_simulated = 1`.

## Known limits
- Synthetic data: the model has learned the generator's patterns, not real attackers.
- Live windows only match training if they look like training rows (e.g. training always has >= 1 login attempt; an
  attacker who never logs in, or a very low-and-slow attack, can score as normal).
- Isolation Forest misses ~15% of simulated attacks at the chosen threshold; a human must still review alerts.
